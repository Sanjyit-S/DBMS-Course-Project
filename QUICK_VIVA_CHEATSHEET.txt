[REPORT 2] OCCUPANCY & LOAD FACTOR (AGGREGATES + CASE WHEN)
SELECT f.flight_id, f.flight_number, a.model, a.total_capacity, COUNT(t.ticket_id) AS confirmed_passengers, ROUND((COUNT(t.ticket_id) * 100.0 / a.total_capacity), 1) || '%' AS occupancy_rate, CASE WHEN (COUNT(t.ticket_id) * 1.0 / a.total_capacity) >= 0.80 THEN 'OPTIMAL' WHEN (COUNT(t.ticket_id) * 1.0 / a.total_capacity) >= 0.50 THEN 'MODERATE' ELSE 'LOW_YIELD' END AS efficiency FROM flights f JOIN aircraft a ON f.aircraft_id = a.aircraft_id LEFT JOIN tickets t ON f.flight_id = t.flight_id AND t.ticket_status != 'CANCELLED' GROUP BY f.flight_id;

[REPORT 3] ROUTE DEMAND & CORRIDOR DENSITY (COUNT DISTINCT + SUM + AVG)
SELECT r.route_id, r.origin_airport || ' -> ' || r.dest_airport AS corridor, r.distance_km, COUNT(DISTINCT f.flight_id) AS flights_count, COUNT(t.ticket_id) AS total_passengers, COALESCE(SUM(t.fare_amount), 0) AS total_revenue, ROUND(AVG(t.fare_amount), 2) AS avg_ticket_price FROM routes r LEFT JOIN flights f ON r.route_id = f.route_id LEFT JOIN tickets t ON f.flight_id = t.flight_id AND t.ticket_status != 'CANCELLED' GROUP BY r.route_id ORDER BY total_revenue DESC;

[REPORT 4] BAGGAGE LOGISTICS & EXCESS SURCHARGES (5-TABLE JOINS + SUM + AVG)
SELECT f.flight_number, r.origin_airport || ' -> ' || r.dest_airport AS route, COUNT(b.baggage_id) AS total_bags, ROUND(SUM(b.weight_kg), 1) AS total_weight_kg, ROUND(AVG(b.weight_kg), 1) AS avg_bag_weight, SUM(b.excess_fee) AS total_excess_fees FROM flights f JOIN routes r ON f.route_id = r.route_id JOIN tickets t ON f.flight_id = t.flight_id JOIN checkins c ON t.ticket_id = c.ticket_id JOIN baggage b ON c.checkin_id = b.checkin_id GROUP BY f.flight_id ORDER BY total_weight_kg DESC;

[REPORT 5] CANCELLATIONS & NET PENALTY RETENTION (ARITHMETIC AGGREGATION)
SELECT COUNT(c.cancellation_id) AS total_cancelled, SUM(t.fare_amount) AS gross_fare, SUM(c.refund_amount) AS total_refunded, SUM(t.fare_amount - c.refund_amount) AS net_retained_penalty, ROUND(SUM(c.refund_amount) * 100.0 / SUM(t.fare_amount), 1) || '%' AS refund_ratio FROM cancellations c JOIN tickets t ON c.ticket_id = t.ticket_id;

[REPORT 6] ON-TIME PERFORMANCE STATUS (SCALAR NESTED SUBQUERY)
SELECT flight_status, COUNT(*) AS count, ROUND(COUNT(*) * 100.0 / (SELECT COUNT(*) FROM flights), 1) || '%' AS percentage FROM flights GROUP BY flight_status ORDER BY count DESC;

[REPORT 7] REVENUE BY CABIN TIER & YIELD (CLASS BREAKDOWN)
SELECT s.seat_class, COUNT(t.ticket_id) AS tickets_sold, SUM(t.fare_amount) AS total_revenue, ROUND(AVG(t.fare_amount), 2) AS avg_fare FROM tickets t JOIN seats s ON t.seat_id = s.seat_id WHERE t.ticket_status != 'CANCELLED' GROUP BY s.seat_class ORDER BY total_revenue DESC;

4. EMERGENCY VIVA DEFENSE RECITALS (MEMORIZE THESE 3 ANSWERS)
================================================================================

1. WHAT IS 1:1 AND 1:N OVER HERE?
"A foreign key is naturally 1:N by default (e.g., one aircraft has many seats). 
To make it strictly 1:1, we place a UNIQUE constraint on the foreign key column. 
For example, tickets to checkins is 1:1 because checkins.ticket_id is UNIQUE. 
A ticket can produce at most one check-in record."

2. HOW DO YOU PREVENT DOUBLE-BOOKING IN DDL?
"Through table-level composite key uniqueness: 
CONSTRAINT uq_flight_seat UNIQUE (flight_id, seat_id) in the tickets table. 
The RDBMS enforces this at the B-tree index level before any row write commits."

3. WHY DID WE DECOMPOSE PASSENGERS AND FLIGHTS?
"Logically, passengers and flights have a Many-to-Many relationship. 
To satisfy First Normal Form (1NF) and prevent insertion/deletion anomalies, 
we decomposed M:N into two 1:N relationships via the junction entity 'tickets'."
