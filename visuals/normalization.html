Stage 0

Universal Relation (UNF)

Severe Redundancy & Anomalies
Initial Universal Relation: Contains repeating groups, multivalued sets, and mixed entity domains.
Runiv = { booking_ref, booking_date, passenger_id, first_name, last_name, email, passport_no, flight_no, dep_airport, arr_airport, sched_dep, sched_arr, aircraft_id, model, capacity, seat_no, seat_class, fare_amt, payment_id, amount_paid, pay_method, pay_status, checkin_id, boarding_pass, baggage_id, bag_weight, excess_fee, cancellation_id, refund_amt }

Identified Anomalies in UNF:
• Repeating Groups: Multiple passengers per booking, multiple flight segments per itinerary, multiple baggage items per check-in.
• Insertion Anomaly: Cannot record an airport or aircraft without an active passenger booking.
• Deletion Anomaly: Deleting a customer reservation inadvertently deletes physical flight schedules and fleet configurations.

Stage 1

First Normal Form (1NF)

Atomic Domains & Composite Primary Key
Definition: All attribute domains are atomic (indivisible) and non-repeating. Candidate key is identified.
Flattened Candidate Key K1NF:
K1NF = { booking_ref, passenger_id, flight_no, seat_no, baggage_id }

1NF Violation (Partial Dependencies Identified):
• {booking_ref} → booking_date (Independent of passenger or flight)
• {passenger_id} → first_name, last_name, email, passport_no (Independent of booking or baggage)
• {flight_no, sched_dep} → dep_airport, arr_airport, aircraft_id (Independent of passenger)
• {aircraft_id, seat_no} → seat_class (Independent of ticket issuance)

Stage 3

Third Normal Form (3NF) & BCNF

100% Dependency Preserving & Lossless
Definition: In 2NF and no non-prime attribute is transitively dependent on any candidate key (every determinant is a superkey).
∀ (X → A) ∈ F+: X is a Superkey of R ⇒ Guarantees Boyce-Codd Normal Form (BCNF) simultaneously!

Theorem 1: Lossless Join Proven

A decomposition D = {R1, R2} is lossless if and only if R1 ∩ R2 → R1 or R1 ∩ R2 → R2 in F+.
• airports ∩ routes = {airport_code} → airports (FD 1) ✓
• aircraft ∩ seats = {aircraft_id} → aircraft (FD 2) ✓
• routes ∩ flights = {route_id} → routes (FD 4) ✓
• bookings ∩ tickets = {booking_id} → bookings (FD 10) ✓
• tickets ∩ checkins = {ticket_id} → tickets (FD 12) ✓
⇒ Natural join reconstructs Runiv without spurious tuples.

Theorem 2: Dependency Preservation Proven

A decomposition is dependency-preserving if (F1 ∪ F2 ∪ ... ∪ Fk)+ ≡ F+.
• Every functional dependency X → Y ∈ F is verified locally within its single projected table via Primary Key or UNIQUE constraints.
• Zero cross-table relational joins are required to enforce any of the 18 minimal functional dependencies.
⇒ Decomposition is strictly 100% dependency-preserving.

Theorem 3: BCNF Compliance Proven

Every determinant in every projected functional dependency is a superkey of its respective relation.
• All determinants {airport_code, route_id, aircraft_id, flight_id, passenger_id, booking_id, ticket_id, payment_id, checkin_id, baggage_id, cancellation_id} are Primary/Candidate Keys.
⇒ Schema satisfies both 3NF and BCNF simultaneously.
