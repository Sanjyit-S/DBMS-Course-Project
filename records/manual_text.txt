What are all attributes required to create a Database for any hotel booking?
Creating a database for a hotel booking system requires careful consideration of various attributes to
efficiently manage the data related to reservations, rooms, guests, and other relevant information. Here
are some essential attributes that you might need for a hotel booking database:

1. Guest Information:
- Guest ID (unique identifier)
- First Name
- Last Name
- Contact Information (phone number, email)
- Address
2. Room Information:
- Room ID (unique identifier)
- Room Type (e.g., single, double, suite)
- Room Number
- Room Rate
- Room Capacity (number of guests it can accommodate)
- Description
3. Reservation Information:
- Reservation ID (unique identifier)
- Guest ID (foreign key to link with guest information)
- Room ID (foreign key to link with room information)
- Check-in Date
- Check-out Date
- Total Price
- Special Requests

a.

(Alias) AS Keyword – SQL aliases are used to give a table, or a column in a table, a temporary
name. Aliases are often used to make column names more readable. An alias only exists for the duration of
that query. An alias is created with the ‘AS’ keyword.
• SELECT column_name AS alias_name FROM table_name;
 SELECT Name AS Student_Name FROM Students;

• SELECT column_name(s) FROM table_name AS alias_name;
 SELECT ID AS Student_ID, BloodGroup AS [Blood Group] FROM Students;
(The above statement creates two aliases, one for the ID column and one for the BloodGroup column. It
requires double quotation marks or square brackets if the alias name contains spaces)

b.

JOIN – A ‘Join’ clause is used to combine rows from two or more tables, based on a related
column between them.

 SELECT Orders.OrderID, Customers.CustomerName, Orders.OrderDate
FROM Orders
INNER JOIN Customers
ON Orders.CustomerID=Customers.CustomerID;

INNER JOIN - Returns records that have matching values in both tables. The INNER JOIN
keyword selects records that have matching values in both tables.
• SELECT column_name(s)

 Introduction to MongoDB
MongoDB is a widely used NoSQL database designed to store and manage largescale data.
Unlike traditional relational databases, MongoDB uses a document-oriented data model where data
is stored in flexible, schema-less JSON-like documents.
CRUD Operations in MongoDB
CRUD operations represent the four core functions of managing data in MongoDB: Create,
Read, Update, and Delete.
1. Create
The "Create" operation involves adding new documents to a collection. This allows you to
initialize or expand your dataset. You can insert one or multiple documents into a collection
at once.
2. Read
The "Read" operation is used to query and retrieve data from a collection. MongoDB
supports a variety of query options to filter and retrieve specific subsets of documents based
on criteria.
3. Update
The "Update" operation modifies existing documents in a collection. You can update one or
multiple documents at a time and specify which fields to update or replace.
4. Delete
The "Delete" operation removes documents from a collection. It can be used to delete
individual or multiple documents based on specified criteria.
