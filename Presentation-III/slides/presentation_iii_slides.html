-- Double Booking Prevention (Physical Topology) CONSTRAINT uq_flight_seat UNIQUE (flight_id, seat_id) -- Geographic Validity CONSTRAINT chk_distinct CHECK (origin_airport <> dest_airport) -- Financial & Physical Safeguards CONSTRAINT chk_baggage_wt CHECK (weight_kg >= 0.00) CONSTRAINT chk_fare CHECK (fare_amount >= 0.00)

Live Record Viewing & Master Flight Manifest

6-Table Relational Join

Live Query Execution

CREATE VIEW view_master_manifest AS SELECT t.ticket_id, b.booking_ref, p.first_name || ' ' || p.last_name AS passenger_name, p.email, f.flight_number, r.origin_airport || ' -> ' || r.dest_airport AS route, f.scheduled_departure, f.flight_status, s.seat_number, s.seat_class, t.fare_amount FROM tickets t JOIN bookings b ON t.booking_id = b.booking_id JOIN passengers p ON b.passenger_id = p.passenger_id JOIN flights f ON t.flight_id = f.flight_id JOIN routes r ON f.route_id = r.route_id JOIN seats s ON t.seat_id = s.seat_id;

Operation 3 Demonstration

Live Record Deletion & Referential Integrity

Safe Deletion Protocol

Targeted Row Deletion Protocol

Each row in editable tables features a direct Delete action triggering an interactive confirmation modal.

The modal previews the targeted tuple and generates the exact SQL statement:

DELETE FROM passengers WHERE passenger_id = 61;

Guarantees that no deletion commits without explicit user authorization.

Referential Integrity Defense

CASCADE Enforcement: Deleting a booking automatically cascades deletions to associated issued tickets.

RESTRICT Enforcement: Attempting to delete an airport with dependent active flights triggers a live foreign key rejection:

FOREIGN KEY constraint failed: Active flight routes referencing 'DEL' exist.

Prevents orphaned records and database corruption.
